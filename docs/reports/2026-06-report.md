# Progress Report - June 2026

Period: June 1, 2026 - June 30, 2026
Report type: Monthly

## Summary

June closed out the Q2 treasury milestone: testnet block production and the
Leios prototype. The Leios work matured from serving Endorser Block data over
N2C into a working prototype - Dingo now forges Endorser Blocks inside the
Praos slot leader, votes with a stake-truncated committee and quorum, and
diffuses votes over a dedicated mini-protocol, all coordinated against a named
Leios testnet (musashi) tracking the IOG prototype spec. Alongside it, Dingo
and gOuroboros landed initial Dijkstra support - block headers, redeemers,
protocol-parameter serialization, and at-tip nonce handling - an early start
on the next milestone.

The rest of the month was correctness and durability work on the paths a
mainnet node depends on: Conway ledger accounting (reward withdrawals, MIR
certificates, pool-deposit refunds, treasury donations, governance
enactment cleanup), Mithril v2 bootstrap with a public sync API, storage and
backfill performance, and continued Blockfrost API alignment. Plutigo
addressed security-review findings and hardened its parser and decoder.

No treasury funds were claimed or moved in June. The M-2 (Q2 Testnet) and M-3
(Infra June) milestones matured on June 30. This report records engineering
work delivered during the month.

Source basis: June 2026 main-branch history in the local Dingo, gOuroboros,

## Treasury Milestone

The relevant treasury milestone is Q2: testnet block production and the Leios
prototype, which matures at the end of June. June brought both halves to a
head. On block production, work centered on making chain selection and forging
safe under real network conditions: pinning to a same-tip peer during
selection, a configurable multi-active header sync strategy, optionally
validating a forged block through chain selection before diffusion, checkpoint-
based chain validation, capping FindIntersect point counts, and fixing
near-tip and epoch-clock stalls. On Leios, Dingo moved from serving Endorser
Block bodies to forging them within the Praos slot leader, added stake-
truncated committee voting with a stake quorum, and gained a vote-diffusion
mini-protocol with Ranking Block integration - with gOuroboros supplying the
CIP-CDDL Endorser Block type, the Leios/Dijkstra block header, and the musashi
testnet definition. gOuroboros also refactored Leios out of the era model,
reflecting the settled understanding that Leios rides on top of existing eras
rather than being one.

## Dingo

- Shipped 17 June releases from `v0.50.0` through `v0.61.0`.
- Advanced the Leios prototype from data-serving to a working node: Endorser
  Block forging integrated into the Praos slot leader, serving forged EB
  bodies, stake-truncated committee voting with a stake quorum, a Leios vote-
  diffusion mini-protocol with Ranking Block integration, pipeline timing and
  stage management, an embedded Leios testnet config, and correctness fixes
  (reject EB hash/slot mismatches before voting, MSB-not-LSB ordering, EB
  backfill, per-connection leios-fetch cooldown). Synced to the `2026w25`
  prototype and renamed the Leios testnet to musashi.
- Landed initial Dijkstra support alongside Leios votes, with Dijkstra at-tip
  nonce calculation and Dijkstra forge protocol-parameter fixes.
- Hardened block production and chain selection: same-tip peer pinning,
  configurable multi-active header sync, per-peer blockfetch metrics, optional
  forged-block validation through chain selection before diffusion, checkpoint-
  based chain validation, binary-search leader-slot lookup, a FindIntersect
  point cap, stale-peer handling, and fixes for near-tip and epoch-clock stalls
  and VRF result-proof handling. Extracted pure Praos selection primitives.
- Deepened Conway ledger accounting: transaction reward withdrawals applied to
  account balances, MIR certificate effects on reward and Ada-pot state,
  POOLREAP pool-deposit refunds at epoch boundaries, treasury kept in sync with
  Conway transaction donations, governance reward-delta replay, removal and
  refund of orphaned governance actions after enactment, cardano-node-shaped
  4-element GetDRepState entries, Conway vote tally over stake credentials, and
  fixes to fee/min-fee handling and a reward-withdrawal underflow.
- Overhauled Mithril bootstrap: a public sync API, a v2 database, transient-TLS
  retry for v2 immutable-archive downloads, download keepalive and pipeline
  work, chain rewind for catch-up, empty-snapshot handling, and skipping
  consumed-input recovery and snapshot recalculation during Mithril backfill.
- Continued storage and performance work: improved Badger recovery and
  configurable compression, a sharded block LRU cache, SQLite auto-migrate,
  fixed-shape SQL for the SQLite API-backfill write hot paths, reduced deferred
  index-rebuild cost after API backfill, per-epoch proposal-tally caching, and
  gating the S3/GCS blob plugins behind a build tag.
- Aligned the Blockfrost-compatible API with the OpenAPI spec (stake-account,
  transaction-detail, and network endpoints; Conway-era protocol parameters;
  network locked-supply computation), moved the public API packages under an
  `api` namespace, and added offline metadata fetching.
- Improved peer governance and networking: blockfetch backpressure, rate-
  limiting or closing peers stuck on a missing point, plateau handling, and
  recovery from chainsync stalls after disconnect.
- Strengthened testing and quality: replaying conformance scenarios through the
  real block-ingestion path, a shared ouroboros-mock Conway chain fixture,
  Antithesis txpump genesis loading, enforced package import boundaries, and
  nilaway/static-analysis cleanup. Added selectable text/JSON log output and
  made metrics-listener failures non-fatal.

_Out of scope for this proposal:_ June also included initial work on a Midnight
indexer inside Dingo (config parsing, a gRPC server lifecycle, cNIGHT block
scanning, governance/Ariadne/candidate scanning, metadata models, and vendored
protobuf definitions). This is partnerchain/ecosystem work and is not charged
against the treasury milestones; it is noted here only for completeness of the
main-branch record.

## gOuroboros

- Shipped June releases `v0.180.0` through `v0.186.1`.
- Added the Leios Endorser Block type per the CIP CDDL, the Leios/Dijkstra
  block header, and the musashi Leios testnet network definition; refactored
  Leios out of the era model; and synced to the current Leios prototype.
- Landed Dijkstra ledger support: redeemer handling, cost-model serialization
  in Dijkstra protocol-parameter updates, and `mint 0` encoding for Conway and
  later.
- Expanded governance and ledger helpers: constructors for Conway proposal
  procedures and governance actions, voting-procedure helpers, metadata JSON
  helpers, a `GetAccountState` local-state query, cardano-node-shaped 4-element
  `DRepState` encoding, and a rewards-calculation fix for when total pool
  rewards fall below the fixed fee.
- Hardened correctness and robustness: widened integer overflows for 32-bit
  targets, handled null/undefined map keys in `Value` decoding, fixed
  blockfetch panics on invalid configurations, differentiated
  validation-enabled from validation-ran in the pipeline, and corrected opcert
  sign/verify to operate over raw `OCertSignable` bytes rather than CBOR.
- Sharded CBOR cache locks for throughput and tightened VRF-benchmark and
  TxSubmission message tests.

## Plutigo

- Shipped June releases `v0.1.14` through `v0.1.16`.
- Addressed security-review findings and hardened the parser and decoder:
  bounded application width to the parser depth limit, decoded string escapes
  as Unicode code points, rejected trailing bytes and validated the version
  before term decode, and turned an unhandled term type into an explicit panic.
- Improved CEK correctness: reset-on-full eviction for the ed25519 and
  dynamic-int caches, a typed `BuiltinError` from builtin argument validation,
  optional skipping of the final slippage flush, and 32-bit target support.
- Continued the performance push: `dataListValue`/`dataMapValue` fast paths for
  `dropList`, sharded locks for the ed25519 verification cache, and single-pass
  JSON decoding for `PlutusData`.
